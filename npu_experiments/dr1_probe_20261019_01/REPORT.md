# 工况诊断NPU兼容性与PL资源摸底：首次离线交付

2026-10-20，Asia/Taipei。目标器件DR1M90GEG400、speed2，TD 6.2.2.200067。
本轮获得了官方工具的A模型预处理/量化结果，以及五种合法配置的独立门级资源。
其中最小Slice的Tiny预设另完成100MHz独立布局布线。
**尚未获得Alnpu运行时逐节点分配或指令图，不能宣称模型已经在NPU运行，也不能确定A的最终最小软核。**

## 1. 资源结论先行

使用官方Video_NPU1.1生成器和网络预设，不修改加密RTL，不删除必需算子。
下面是**原生综合、map/pack与legalize后的独立夹具实测**；未合并运动系统。
全部控制、访存、时钟、复位和中断接口保留，虚拟IO边界为203输入位/230输出位。

|合法配置|IP本体LUT6容量等效¹|夹具LUT6容量等效¹|夹具Slice²|寄存器|ERAM|DSP|
|---|---:|---:|---:|---:|---:|---:|
|全算子＋Resize＋YOLOv5，CSC关闭|30,410|30,830|33,082|22,527|116|84|
|全算子，视觉前后处理关闭|20,234|20,654|22,164|15,109|59|53|
|Tiny预设，视觉前后处理关闭|10,524|10,943|11,045|8,878|35|21|
|MobileFaceNet预设，视觉前后处理关闭|13,893|14,313|15,386|10,732|29|32|
|V3预设，视觉前后处理关闭|12,508|12,928|13,882|9,549|15|29|

¹ 门级容量代理，**不是最终布线报告的LUT6计数**。夹具值取工具pack后的
`Slice − reg-only Slice`，也等于顶层`with luts + with adder + used ram`；
IP本体值取直接IP实例一行的`logic lut + ripple + dram lut + shifter lut`。
只统计一层，不将父子模块重复相加。工具明确提示门级LUT/Slice需布局后复核。
`#lut`原始原语总数、`#lut6`六输入原语数都不能误作总LUT6等效。

² Slice是整个独立夹具的pack结果；层次表未单列纯IP本体的Slice，不捏造其值。
夹具比IP本体多419/420个门级LUT容量单位，来自边界/顶层；寄存器、ERAM和DSP均在IP实例内。
该差值**不是**真实PS/GP/HP互连开销。

只去掉视觉前后处理就实际减少10,176个夹具LUT容量单位、10,918 Slice、7,418寄存器、
57 ERAM和31 DSP；不是按层次表手工扣模块的估算。不同预设生成宏与实际面积均发生变化，
证明裁剪改变了硬件；模型权重只有几KB不会自动消除这些电路。

当前测试中Tiny的Slice最少，V3的ERAM更少；不存在“看权重KB或只看RAM就能选最小IP”的结论。
这些是**合法预设的资源包络**，不是A模型已经通过运行库资格的最小配置。

### Tiny的100MHz独立布局布线复核

采用实际STA读回100MHz、同源1:1关系的两接口时钟，16线程完成独立布局：
**11,105 LUT6等效、11,931 Slice、9,112 Slice寄存器、35 ERAM、21 DSP、2 GCLK**；
PLL/LCLK/SCLK/MLCLK/IOCLK均0。这里的LUT6是工具布局后的直接容量计数。
直接IP实例为10,884 LUT6等效，边界/顶层差221；寄存器/ERAM/DSP均在IP内，2个GCLK在夹具顶层。
Slice仍是整体pack/布局结果，未伪造可分离的纯IP Slice值。
布局STA setup +4.517ns、hold0，最拥塞1% tile平均routing util 74.398649%。
随后从同一place.db在独立目录完成布线，**资源数保持不变**；最终setup **+1.012ns**、
hold **+0.020ns**，67,957路径全部完成、overflow0。最终2 GCLK、11 SCLK，
PLL/LCLK/MLCLK/IOCLK为0；feedthrough6,974另列，不重复加到逻辑Slice。
这是独立虚拟边界的内部布局布线证据，不是运动系统合并或真实PS/HP边界时序验收。
route STA coverage为95.56%；虚拟AXI边界没有真实PS/互连输入输出延迟，不能声称全部接口时序签核。
原place.db逐字节未变，见physical_tiny_route100/status.json、route.area、route.timing和route.status。

## 4. A模型与当前工具链能接受到哪一步

已在`SDK.2025.7`的`sdk/app/npu/scripts`找到并执行官方AL_onnx_pass、检查、拆分和静态量化工具。
实际示例采用Arm NN32.1.0/ONNX parser24.6.0，读量化ONNX并在运行时优化；
它与UG1214描述的tmfile离线指令流程不同。版本和缺失项详见TOOLCHAIN.md。

探针A原始结构为68→32→16→3，隐藏层ReLU；2,736权重、51偏置，逻辑MAC2,736。
先做固定种子20261019的非零权重探针，再做小规模公开数据训练。

|实际工具检查|结果|
|---|---|
|标准ONNX原始Gemm transB=0|ONNX合法，但官方AL检查器明确拒绝|
|转置常量权重、Gemm transB=1|数值等价，官方检查器通过|
|二维[1,68]直接进AL总入口|实际IndexError，脚本硬编码读取四维输入|
|[1,68,1,1]→Flatten→同一MLP|原模型固定输出差0；官方检查器与总入口预处理/量化成功|
|官方检查器SoftNPU清单|A为空；没有Pooling、Add、Concat、PReLU、Resize或YOLO需求|
|INT8/UINT8输出|成功生成QDQ ONNX，固定主机参考已验证|
|Alnpu实际优化、指令分配、加载/运行|**未执行/未验证**；当前附带后端为AArch64库，不能在此Windows主机执行|

因此答案是：**当前已取得的官方主机工具接受经过等价导出适配的A，并可量化；
不能将这句话扩大为“当前DR1运行链已接受且全图在NPU执行”。**
没有用伪后端、CPU运行或ONNX导出成功代替NPU成功。
种子探针及最终主机模型均保留活输入，输出随输入变化；没有观察到主机预处理把网络折叠为常量。
最终NPU指令图的折叠/融合仍无输出可检查。

逐节点清单见`operator_assignment.csv`，包括所有浮点、简化、量化及B几何探针。
“Hard候选”来自手册FC/ReLU能力与官方浮点检查器，不是实际分配证明。

|A处理|证据支持的候选落点|实际落点|
|---|---|---|
|3个Gemm/偏置、隐藏ReLU|Hard NPU候选|未验证|
|Flatten|布局/视图处理候选，无Soft清单需求|未验证|
|QuantizeLinear/DequantizeLinear|SDK QDQ格式/融合或边界处理|未取得后端分配；不能擅自归Hard或PS|
|统计、训练均值/标准差归一化、argmax/解释|拟在PS处理，当前主机参考执行|无板端PS运行证明|

UINT8最终图含3 Gemm、1 Flatten、4 QuantizeLinear、10 DequantizeLinear；ReLU在主机量化图中融合。
INT8含3 Gemm、2 ReLU、1 Flatten、6 QuantizeLinear、12 DequantizeLinear。
QDQ模型的外部输入/输出仍为FLOAT；量化权重和内部范围不等于全图数据都已在NPU中完成转换。
示例默认`Alnpu,CpuAcc,CpuRef`，仅凭其程序运行成功也可能包含CPU后端。
本轮没有证明CPU回退一定发生，也没有取得A的实际CPU回退列表。

**A所需最小Soft NPU仍未确定。** 官方检查器“需要0种Soft算子”不等于“需要0个PL Slice”。
缺的是无Soft图的硬件/驱动初始化契约、Alnpu与IP1.1兼容资格及最终后端分配。
Tiny是本轮测试里最小的合法预设容量参考，不能直接命名为“A的最小实现”。

## 5. 公开数据、量化参考与B的边界

数据为Helwig/Pignanelli/Schütze的UCI447液压实验台数据，CC BY4.0，2026-10-20取得；
来源、DOI与许可证链接在README保留。不是机械臂485数据。
2,205个60秒周期；17路信号各在原生1/10/100Hz上取均值、总体标准差(ddof=0)、最小、最大。
同一周期聚合，无需将低速信号插值为高速信号；检查了17个矩阵形状及全部有限值。
标签为profile第三列泵内漏0/1/2。stable flag=0稳定，1可能未稳定；全部保留，该标志不是输入特征。

完整周期互斥划分训练1542、验证331、测试332；标准化仅拟合训练集。
固定种子、小MLP训练最多80epoch、Adam lr0.001、batch64，按验证交叉熵选权重。
随机周期划分仍可能有相邻周期/工况相关性，不能当作跨机器、跨工况或机械臂泛化证明。

B仅做兼容性几何探针，不训练：

- 128×17、16/32通道、k=3的Conv1D，原2,499参数、301,152逻辑MAC；官方检查器拒绝3维卷积格式。
- 合法ONNX的1×3 Conv2D映射与原参考等价，但官方检查器警告非方形核/相应padding不能由ALNPU加速。
- 零嵌入3×3方形核保持输出（固定输入差在参考容差内），卷积形状检查不再告警；
  存储参数增至7,203，卷积填充MAC上界增至903,264，不能把原30万MAC当其硬件开销。
- 三种表达的GlobalAveragePool均被标为不能由ALNPU加速。启用NN_POOLING不证明支持平均池化；

B固定向量与完整清单保留。未生成“B可部署最小IP”，未以B主机ONNX执行冒充NPU运行。
若将来继续，建议明确100Hz共同时间轴、1.28秒窗口、低速通道零阶保持的语义，窗口不得跨周期，
训练/验证/测试仍先按周期分割；这只是待验证方案，本轮没有执行该对齐/窗口训练。

## 7. 对四个目标问题的回答

1. **小FC能否被当前工具接受？** 官方主机预处理/量化可接受等价适配的A；实际Alnpu后端加载、指令图和NPU执行尚未验证。
2. **实际最小Soft NPU多大？** A浮点检查器无Soft算子需求，但最小合法可部署硬件未定。
   已实测最小预设是Tiny：独立布线夹具11,105 LUT6等效、11,931 Slice、9,112寄存器、35 ERAM、21 DSP；
   其中直接IP实例10,884 LUT6等效，边界/顶层差221，夹具另用2 GCLK/11 SCLK。
   Resize、CSC和YOLO后处理可经官方开关关闭；不能自行改成空网络模式或任意逐算子剪裁。
3. **合并会超多少或余多少？** 全算子去视频仍在门级算术预算超7,668 Slice；Tiny门级暂余3,451 Slice，独立布线计数预算只余2,565 Slice，外部互连未计。
   已有系统本身100MHz失败且局部拥塞高，实际合并及布线余量未知。
4. **阻塞来源？** A的主机算子/量化不是当前主要阻塞；缺实际后端分配、IP1.1软件匹配及无Soft图部署契约。
   完整配置存在明确固定PL开销和现有Slice预算冲突；小预设缓解容量，但未解除集成/时序风险。
   B另有Conv1D映射与GlobalAveragePool算子障碍。不能据完整视频配置过大否定所有NPU路线。

下一步应先取得“空Soft算子清单”的最小硬件/驱动契约及Alnpu/IP1.1匹配说明；若仍必须选择Tiny等预设，
先测真实GP/HP仲裁和时钟复位外围开销，并修复现有运动系统100MHz时序，再决定完整隔离合并。
本轮未以未经模型/运行库资格确认的预设直接改造或合并主线。B暂缓，不能靠打开MaxPool选项解决平均池化。
