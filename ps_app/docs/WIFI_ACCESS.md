# 独立 Wi-Fi 测试权限对照与 PS 接入边界

已读取项目现有 `bsp/wifi/http/server.py`、`README.md` 和 BUILD_STATUS 相关记录。本轮没有连接板卡或修改 Wi-Fi 服务。该服务的历史实板结果只证明独立诊断 HTTP 的资格，不能移记为 PS 命令/HMI 的 LAN 验收。

|现有 Wi-Fi 只读 HTTP|PS 主机基线与后续接入|
|---|---|
|root launcher 读取 root:0600 的独立 salted verifier，O_NOFOLLOW 打开|PS当前独立随机 token + HttpOnly/SameSite session + CSRF；不读取Wi-Fi口令或复用诊断账户。生产账户/写权限机制待批准。|
|绑定无线设备 SO_BINDTODEVICE，再清空附加组并降到 wifihttp UID/GID498|生产PS应使用单独非root服务账户；现有UID498的只读职责不扩展为运动权限。真实owner保持自己的最小设备权限，PS不获得任意MMIO/DMA入口。|
|固定只读 GET 路由；拒绝路径遍历和所有写方法|PS静态资源及日志同样固定路由，日志只收逻辑ID/筛选；PS写命令另有认证、CSRF、控制权和执行互斥，不挂到旧服务的/files。|
|0.0.0.0:8080但套接字限制在无线接口|PS当前回环:18083，Host/Origin显式回环白名单；未增加0.0.0.0或关闭Origin验证。LAN接入需明确接口/地址/端口及精确origin白名单，独立端口不替换8080。|
|本地TTY配置凭据、低权限提供批准导出，HTTP请求不采集设备|PS也应由本地批准流程配置独立凭据及日志目录权限；日志下载/查询不采集设备，不含凭据，不允许任意路径。|
|文档已明确板端墙钟可能无效|PS日志当前始终 wall_time_valid=false，以boot_id内单调时钟过滤，不显示为可信日历时间。|

继续沿用首版 HTTP 的已确认需求，不擅自新增 HTTPS 门槛。HTTP上的认证与命令完整性策略仍需项目评审，不能因只读HTTP已验收就假定运动授权完成。

本轮结论：复用“独立凭据、固定路由、无线接口约束、最小权限、只读导出、不信任墙钟”的设计原则；保留现有诊断服务边界。本次不部署启动器、不打开LAN监听，也不改变账号或设备权限。生产LAN写授权/控制权策略、进程账户/owner IPC、凭据生命周期与地址变化处理集中列为待确认；无需阻塞本轮主机整改和模拟回归。
