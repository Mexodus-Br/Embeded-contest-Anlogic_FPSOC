# D1 整改与接口增补

2026-10-22。本文是本轮主机实现边界，不冻结需求基线中的开放项。原始接口文档保留；发生差异时以本文和当前生成 schema/测试描述本目录行为。Golden 算法和 PL/GP/MOT2/遥测位值没有修改。

## 已完成

- R1：方向按下时固定 boot/STOP 代际。refresh 返回后、启动发送前检查当前会话、released 和代际；全局 STOP 同时取消本地待启动会话。迟到应答不能恢复启动资格，旧异步函数不清除新会话。
- R2：同一监听地址有界接纳。最多48个待解析连接，接纳每批16个、轮询10ms、请求头16KiB、未完成接纳总期限1秒，满额淘汰最旧待解析连接；不在接纳线程读阻塞 body 或发送响应。普通工作槽32个，STOP/状态独立控制槽4个。控制 body 最多1KiB且必须已经完整到达才占槽；认证、CSRF、Host/Origin 继续检查。普通连接满额直接关闭，不等待其5秒读写超时才接纳 STOP。数值是测试限额，非已批准生产指标；无法保证无限恶意流量或操作系统资源耗尽下的时延。
- R3：命令/方向 ID 使用能力检测后的 `crypto.getRandomValues`，不依赖 SecureContext 的 randomUUID。缺少安全熵则拒绝提交，不用 Math.random 降级。
- R4：编译选项与尾部链接库分开，GCC 构建可复测。增加显式 SDK 编译器入口。
- 日志增加跨启动保留段读取、boot 枚举、按 boot 筛选和详情、认证固定快照 JSONL 下载；页面可选择启动实例。
- 后端选择显式，hardware 未交付则启动失败。模拟注入是单独 capability，默认关闭；执行后端接口移除故障注入，另由 SimulationControl 承担。手动段显式携带目标、提交 ID、duration。
- 测试源、参数、构建入口和文档整理到 ps_app，原来件及其他工作区修改保留。

## 日志主机契约

1. `GET /api/v1/logs/boots` 返回 `boot_ids`、`current_boot_id`、`history_incomplete`、`archive_errors` 和 `archive_retired`。仅服务端读取批准的 `events.jsonl`、`events.1.jsonl`～`events.3.jsonl`，不递归、不接受路径、不读取任意文件或符号链接段。
2. `POST /api/v1/logs/snapshots` 的筛选可加 `boot_id`；省略仍只选当前启动。单调时钟范围仅在指定启动内比较；不提供不可信日历时间或跨 boot 的时间排序。未知/过保留期 boot 返回 LOG_RETIRED，格式非法返回 FORMAT。
3. `GET /api/v1/logs/{event_id}?boot_id={boot_id}` 以两个 ID 定位；省略 boot 保持当前启动行为。事件 ID 在不同启动中可以重复。
4. 原分页及 `GET /api/v1/logs/export?snapshot=...` 不变；元数据的 boot、筛选、计数、上下边界、truncated/gaps 与内容一致。固定快照不因新增/轮转变化；60秒过期、最多4个快照，每个最多10000条/16MiB。只有认证后才能读取和下载。
5. 启动只扫描4个固定段，每段最多4MiB+16KiB、单行8192字节；历史索引最多10000条/16MiB，超额移除较旧记录。坏行、截尾、超额、非普通段文件都有计数；历史完整性一律标为未知（gaps=true），不以“当前未发现坏行”声称过去无丢弃。当前启动的队列/丢弃/写失败指标不伪装成历史指标，历史读取问题由 boots 元数据报告。
6. 写入为有界异步队列；生产者尝试锁失败也可能丢弃并计数；入队不等于落盘。当前历史最多10000条，单条最大约8KiB，四快照及索引还消耗额外内存，尚未做板端1GiB资源资格验证。flush不是掉电持久性保证；强制结束进程可丢弃队列尾部。

启动读取历史发生在服务开始接受请求前；日志查询和下载不持有运动互斥锁，不直接消费GP/DMA。历史重读只限留存文件，不承诺恢复已轮转删除或未落盘的事件。所有容量、保留及延迟仍属 host fixture，生产 OPEN-08 尚待批准。
