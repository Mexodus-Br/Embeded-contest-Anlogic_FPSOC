## 配置和采样率

按固定顺序30/33/39/3A/3E设置五个unsigned32 period_us。period=0或query_mask对应位=0禁用；每项频率为1,000,000/period_us Hz，不要求整数Hz。首版各从机共用这五周期，配置地址列表仍沿用编译参数，M4未定不启用。

配置粒度是**每轴、每查询的逻辑请求起点目标周期**，不是总线总帧率、有效应答率或NPU推理率。三轴50Hz的30意味着每秒150条30请求；重试不会算作第二个采样点，训练端按epoch/request_us/sequence/attempt识别。实际有效率、抖动、遗漏、通信错误和FIFO丢弃分别统计。

建议profile（具体频率尚未作为用户冻结值）：

|查询|兼容默认候选|训练快采候选|
|---|---|---|
|30编码器|8Hz / 125ms|50Hz / 20ms|
|33接收脉冲|2Hz / 500ms|10Hz / 100ms|
|39误差|8Hz / 125ms|50Hz / 20ms|
|3A使能|1Hz / 1s|5Hz / 200ms|
|3E保护|1Hz / 1s|5Hz / 200ms|
|三轴正常请求合计|60次/s|360次/s|
|正常隔离/最短请求起点间隔|10ms / 10ms|1ms / 1ms，仿真候选|

异常隔离保持10ms，总响应超时10ms、字节间2ms、DE前后保持/接收屏蔽各10us沿用已确认值。全零暂停新任务；enable=0不取消已在途逻辑请求及其最多一次重试。

## 原子配置接口建议

新增period_us打包输入160bit（低32bit为30），保留五位mask，同时提供cfg_valid/cfg_ready和cfg_applied。提交期间输入保持稳定，握手锁存完整shadow配置；每次最多一个待应用配置。暂不接GP，后续映射另立任务。

配置在已在途请求、最多一次重试及必需的隔离均结束后原子应用；UART应答解析仍用在途锁存的查询/长度。period和mask都通过提交路径生效，避免mask先变而周期后变。没有在途任务时可直接应用。保持原始v1顶层作为兼容接口；扩展使用单独rs485_multirate顶层，不能静默改变原query_mask即刻输入的既有行为。

每次应用输出cfg_revision和cfg_apply_sequence（下一新逻辑请求编号），以及有效配置供采集端记录为运行元数据；重试仍归属于原配置。256bit数据记录布局不变，无剩余位可随意塞入配置版本；若未来必须把配置事件一起入FIFO，需要另行冻结记录类型或新版布局。未接采集软件前，训练数据运行清单必须保存配置、系统epoch、对应sequence范围及变更信息。

配置检查拒绝越界或无法满足带宽预算的组合，保留旧配置并返回cfg_error，不默默缩频。允许周期范围建议1,000..2,147,483,647us或0；周期下限不是每项均能达到1kHz的保证。隔离/最短间隔采用选定编译profile，首版不提供随意绕过电气及迟到验证的热修改入口。

## 到期任务调度

为每个启用的(地址,查询)维护理想起点next_due_us。使用外部系统64bit/1MHz time_us，不生成新epoch。用有符号模差比较到期时间，配置周期/差值保证在半个64bit范围内；统一PL重配置重建时间epoch，模块复位清调度状态但不改外部计数。

配置应用后各任务首次到期设为应用时间。只维护每任务一个到期项，不按到期次数排无限队列。总线空闲、隔离完成且最短起点间隔满足时，选择已到期任务中next_due最早者；相同到期时间使用轮转游标，避免固定偏爱E0或30。没有到期任务则保持DE=0等待，绝不广播或并行请求。这是按理想到期起点排序，不承诺硬实时deadline或三轴同时采样。

实际发出请求时设now=DE上升时间，计算missed=floor((now-next_due)/period)，漏掉的旧槽合并，next_due += (missed+1)*period。因此保持周期相位且不突发补发；迟到超过一个周期才计漏采，迟到少于周期计lateness。饱和累计missed_release，另记录max_lateness_us。除法等实现可用有界迭代/扫描，必须在后续100MHz综合与仿真中验证调度开销；本设计不预判组合大除法能通过时序。

一次逻辑请求含初次尝试和至多一次重试；重试不新增周期任务，不改变sequence/request_us。事务不被其他任务抢占，其他到期任务只保留一个合并项。超时/重试将造成采样抖动，不能把50Hz目标解释为每20ms都有一个有效应答。FIFO满保持既有整记录丢新和统计规则，仍不阻塞调度。

## 故障节点退避

每节点维护连续逻辑通信失败数，失败定义为一个逻辑请求最终无有效应答，涵盖超时、截断、UART framing、checksum、错误地址；初次失败但重试成功不算逻辑失败。有效应答清连续失败数；3E报告保护状态是有效业务数据，不算通信失败。FIFO满丢弃有效记录也不触发节点故障退避。

第三个连续逻辑失败后该节点所有普通任务暂停500ms，其他节点继续调度。暂停期间不积压采样队列；记录node_offline、failure_streak、cooldown_until_us及skipped_backoff统计，不能把暂停当作收到零值。BUS_BUSY是总线级异常，不能据此把某一节点判离线；它单独统计。

500ms到期后只产生一个恢复探测任务，选该节点启用的查询中周期最短者，同周期按轮转决定；不偷偷发送用户禁用的3E。探测遵守相同的隔离/重试/帧校验，参与最早到期调度，不能抢占在途事务。成功后恢复普通任务，next_due重基到探测完成时间，避免补发500ms旧请求；失败则再次等待500ms，不无限指数增长。全零mask不探测；再次开启后恢复到当前时间，不补发关闭期间任务。故障节点探测会占总线，健康节点目标率在异常期间也可能降低，但不会被无限阻塞。

## 带宽核算与可观测性

工具tools/rate_budget.py引用schema.json的波特率、请求/应答长度和DE参数，以每种查询的频率估算：

`cost(q) = max(min_start_gap, wire_time(q) + DE_pre/post + response_start_bound + normal_guard)`

`normal_load = slave_count × Σ(rate(q) × cost(q))`

响应开始上界暂按200us作**规划假设**，包含DE释放到应答起始的时间并必须大于接收屏蔽；不是实际固件已测保证。没有额外字节间隙的连续响应也是估算前提。正常占用门槛建议75%，预留异常和调度余量，但该门槛本身不是最坏情况下时限证明。周期/占用检查可以由配置主机工具完成；若直接开放裸RTL输入，还必须具备同等验证机制，不能只依赖文档承诺。

估算结果见evidence/rate_budget.json：兼容60次/s约65.85%正常服务预算，训练候选360次/s约71.26%；若仍用10ms等待却请求训练频率则约395.26%，必须拒绝。估算值含空等时间，纯线上传输分别约4.53%/27.34%。快速profile只有在响应/字节间隙、迟到和模块换向经测量后才可用于实板；原协议无应答命令码/事务号的关联限制不因新调度消失。

建议新增每任务scheduled/sent/valid/missed/max_lateness以及每节点逻辑失败/退避统计，均明确位宽和饱和行为。NPU训练按实际event_us对齐，记录request_us与event_us的延迟，跨查询字段异步采样，不假定一组字段同时获得；缺失、重试失败、离线和FIFO丢弃保留掩码与时间间隔。模型推理率与采集率独立，系统运动与最终急停仍独立于此调度。
