# RS485位置来源与HOME方向核对

2026-10-26。用户本次确认：XYZ依据RS485反馈；机械计算参考原厂固件；HOME朝Z数值变大的方向，退离与HOME相反。用户补充报告驱动板脉冲计数随方向增加或减少，作为0x33方向/计数对账的切入点。以下是文档/源码核对与离线数值计算，未连接驱动器；用户报告与本任务实测分开登记。

## 驱动器是否返回位置相关数据

结论：**SERVO42C手册定义了单轴编码器反馈，未定义机器人XYZ反馈。** 可用三轴0x30反馈，经机械零点、符号、传动比和FK重建XYZ；当前尚无这条实机发布/标定/FK链路，因此XYZ保持unknown。

原始来源为工作区外只读资料 `D:/Works/Embedded_contest/docs/MKS-SERVO42C/User Manual/MKS SERVO42C User Manual V1.1.2.pdf`，第11–13页；已提取文本并视觉核对第12页，没有修改/哈希该PDF。

|查询|手册返回|对XYZ的作用|
|---|---|---|
|0x30|校准后电机的编码器carry:int32和value:uint16；value 0..FFFF，越界进/借位|真实单轴位置来源候选。应答总8字节=地址1+数据6+checksum1；需实板确认实际固件遵守此格式及STP并发行为|
|0x33|收到的命令脉冲int32；总6字节|不是编码器，不能替代真实位置|
|0x39|控制目标角度与实时角度的差，signed16；总4字节|误差状态，不能单独提供绝对XYZ|
|0x3A|EN状态枚举；总3字节|状态，无XYZ|
|0x3E|堵转保护状态枚举；总3字节|保护资格，无XYZ|

第11页明确校验为CHECKSUM-8，线上应答没有查询命令回显/事务号；不当作Modbus，不向驱动器发送任意写/校准/使能命令。校准命令0x80会引发动作，不能由本次只读核查推导许可。

厂商[官方V1.1发布说明](https://github.com/makerbase-mks/MKS-SERVO42C/releases/tag/MKS-SERVO42C-V1.1)也提到0x30编码器、0x33脉冲和0x36轴角度，并指出重新使能可能返回旧目标。**本地V1.1.2手册5.1没有0x36完整定义，本次不新增0x36轮询，也不因发布说明假定实物版本一致。** 本地Firmware/firmware.txt不是可核验固件。断电/重新使能后的多圈carry和原点连续性仍需实测，不能默认多圈绝对位置持久。

## 机械模型与缺少的标定

原厂参考固件为 `D:/Works/Embedded_contest/docs/Arduino_firmware/`。实际运行的 `robotGeometry.cpp::calculateGrad`硬编码 R=83.7、r=30.4、L=150、l=280mm；不要误用config.h中没有进入该公式的140/160/50长度替代。`RampsStepper`使用4.5传动比、200整步/转、16细分，角度到命令步数因子为4.5×200×16/(2π)。Golden当前正是这套实际表达式；本次未改Golden。

轴序：原X=Higher→high，Y=Lower→low，Z=Rotate→rot；普通脉冲中inverse=true时正增量DIR=1、负增量DIR=0，与cf764ad及完整PL的逻辑极性一致。这里的原“Z电机”不是末端笛卡尔Z单轴；实体A0/A1/A2接哪根机构臂仍须当次核对。

按手册编码约定，候选展开量应为 `N_i = int64(carry_i)*65536 + uint16(value_i)`，再以实测参考做 `q_i = q_ref_i + sign_i * (N_i-N_ref_i) * 2π/(65536*gear_ratio_i)`。这是待实测确认的换算约定，不把microsteps乘进编码器分辨率，也不把电机侧角直接当关节角。

还缺每轴地址↔机构臂映射、编码器正向、机械参考对应的N_ref/q_ref、多圈/重启连续性和三轴异步采样最大时间差规则。原固件setup和homeSequence直接setPositionRad(-0.48)，并把插补位置设为(0,0,-140)；这不是新系统实测编码器零点，不能照抄成为真实位置。读取0x30只解决原始反馈来源，不能省去参考和FK分支检查。

## HOME方向核对与处理

用户确认的是笛卡尔+Z和退离-Z。离线Golden原公式在中心附近得到：

|XYZ mm|三轴命令步数(high/low/rot)|
|---|---|
|(0,0,-141)|-1059/-1059/-1059|
|(0,0,-140)|-1090/-1090/-1090|
|(0,0,-139)|-1123/-1123/-1123|

因此在该参考模型/这一区域，+Z对应三轴负增量、DIR=0；原固件HOME也以!inverse=true取反后使用LOW。**该离线例子不是实板运动指令，也不足以证明所有姿态和接线。** 生产HOME还需逐轴接线/限位方向核验与参考/退离距离、速率、最大行程/超时确定。

完整PL PROFILE2的C_HOME_DIRECTION=3'h5，即A0/A2为1、A1为0；参考步数100/-200/300、短搜索/退离参数为测试夹具。不能把它当用户确认的+Z生产HOME。为防止HMI误用，最终软件HardwareBackend在入队前以`PRODUCTION_HOME_UNAPPROVED`拒绝HOME，保留明确OPEN/STOP/维护恢复；不会靠网页提示来把夹具HOME放行。待生产参数定稿后，需要独立PL配置、16线程完整P&R、匹配启动链和受影响安全/运动/波形回归，再解除对应软件限制。

第2阶段先验证真实三轴0x30格式、变化、时间/代际和安全链，不执行HOME或机械运动。第3/4阶段的XYZ/方向仍待原始帧发布、标定和FK完成；拒绝不代表模拟替代。当前不能登记为完整产品位置功能已完成。

## 以带符号脉冲计数作为切入点

用户补充的正/负计数行为可用于核对三段链路：PL实际输出STEP累计增量 → 驱动板0x33接收脉冲增量 → 驱动板0x30编码器实际变化。按轴保留原始值、来源时间、采集/运输代际和有效性，不把三者压成一个“位置”。

1. 第2阶段STEP隔离时先读0x33基线及重复值，不发送脉冲。其稳定值不能单独证明驱动器失能/机械静止。用户报告的方向计数行为记为USER_REPORTED，待第3阶段当次许可后以最小正/负脉冲分别确认数值比例与符号。
2. 第3阶段在停稳、同一电机配置/计数epoch、已知细分和轴映射下比较增量；0x33是signed32，须区分回绕、清零、重新上电与新会话。只有有界变化小于半个计数范围且无重启/重置歧义时才展开差值，否则标unknown。PL/采集generation不是驱动器未重启的证据。
3. RS485与PL快照异步，不能要求任意两帧瞬时相等；使用请求/事件时间和停稳前后窗口对齐。计数不符时定位DIR极性、接线、输入边沿/脉宽、细分/脉冲倍率、遗漏或时序关联，不通过改软件位置掩盖差异。
4. 0x33变化而0x30未按预期变化时，收到命令与实际跟随不一致；结合0x39/0x3E和真实时间判断，停止当次运动并保留证据，不以0x33生成“实测XYZ”。XYZ继续采用用户指定的真实编码器来源，经已标定的传动映射与FK得到。

若后续单独提供基于0x33的XYZ，只能明确标为“驱动接收命令推算位置”，并与编码器测得位置分栏；当前不为此新增伪实测位置或运动资格。
