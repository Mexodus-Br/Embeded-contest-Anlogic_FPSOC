# 合作方如何推进

## 第一步：建立共同输入，不先造六套接口

1. 运行`python tools/smoke.py`，提交工具版本和结果，确认Golden及codec可复用。
2. 根据需求第10节提交一份所有组件共用的接口提案：命令/状态/错误、预览与执行、方向会话、SSE事件、参数与任务、遥测/日志查询。标记待项目方决定的项，附至少一组请求/结果和异常用例。
3. 对未确认的认证、速度/时限/容量/任务循环策略，不自行宣布冻结；测试可注入显式命名的fixture参数，不能默认为实机参数。
4. 项目方确认共用接口后再推进跨组件联调。期间可先开发纯计算、内存解码、文件逻辑、模拟状态机及界面草图。

不要求合作方先改Linux驱动或等待实体板；硬件后端始终可由模拟实现替换。

## 推荐联调顺序

1. 主机Golden/遥测/MOT2参考测试通过。
2. 共用契约确认后，HMI＋命令服务＋模拟执行器形成端到端闭环：合法预览→显式运行→结果；非法/陈旧预览拒绝；执行中STOP。
3. 接入参数/任务、规划库和多点模拟执行；加入示教位置有效/无效、任务断线继续和方向超时停止。
4. 接入冻结遥测回放及结构化日志，验证64位JSON不丢精度和查询负载不阻塞STOP。
5. 按交付检查表移交源码/测试/依赖和边界说明；由项目方交叉编译、接真实后端、集成上板。

## 模拟器需要表达的事实

模拟器至少能显式注入：位置无效、有效命令位置、预览合法/非法、状态变化使预览失效、正在运动、STOP处理中/完成/失败、故障、重启后结果未知、遥测过期/错误/代际变化。所有模拟画面/事件都标明simulation。

不要为了让页面顺利演示而把“未知位置”自动改成零、把预览当运动完成，或让方向输入断线后永久运动。不得用前端定时器代替PS任务执行器。

## 示例不等于已冻结HTTP API

本包只提供算法向量/codec/既有板端参考，没有虚构可直接调用的正式Web端点。API、任务文件和模拟器的精确JSON须按共同提案确认；合作方在交付中附完整schema、版本、错误和测试样本，避免各组件独立发明不同字段。
